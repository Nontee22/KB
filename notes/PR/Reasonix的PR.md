## 学习记录：从 Reasonix 快捷方式修复看版本化目录的设计与缺陷补全

### 一、背景：版本化目录的引入

Reasonix 从 **v1.20** 版本开始，将应用安装路径从固定目录（如 `/opt/reasonix/app`）改为版本化目录结构：

```
InstallRoot/
  reasonix-launcher[.exe]
  current.json
  versions/
    1.20.2/
      reasonix-desktop[.exe]
    1.20.3/
      reasonix-desktop[.exe]
```

这个设计的核心目的是**支持原子化更新**：
- **更新失败时可回滚**：保留旧版本，切回 `current.json` 指向的版本即可；
- **更新成功后可清理旧版本**：删除无用版本，节省磁盘空间。


### 二、问题：快捷方式失效

这个设计带来了一个副作用——**目标路径从静态变为动态**。

以前快捷方式（`.desktop` 或 Windows 快捷方式）里写的是**绝对路径**：

```
Exec=C:\Program Files\Reasonix\app\reasonix.exe
Icon=C:\Program Files\Reasonix\icons\logo.ico
```

版本升级后，旧版本目录被清理，新版本在 `versions/1.20.3/` 下面。但快捷方式里记录的还是旧路径，用户点击后就会报错“找不到应用”。


### 三、作者的尝试：半程自修复

作者其实预见到了这个问题，所以在 v1.19.4 开始就尝试建立**自修复逻辑**，在版本更新时自动检查并修复快捷方式。

**但是这套逻辑只覆盖了一半**：

| 字段 | 是否修复 | 结果 |
|------|----------|------|
| `Icon=`（图标路径） | 已修复 | 图标显示正常 |
| `Exec=`（可执行文件路径） | 未修复 | 点击后启动失败 |

从 PR #7752 的代码可以看出，`repointTarget`（重指向目标路径）和 `fixIcon`（修复图标）是**两个独立的判断分支**，作者只实现了图标修复这一侧。

最终表现就是：**图标看着正常，但点不开应用**——这种“半修复”状态反而比直接失效更让用户困惑。


### 四、官方的最终方案：v1.22.0 完整修复

官方的 **v1.22.0 发行说明** 明确写道：

> **修复旧版 Windows 快捷方式** —— 旧版本的快捷方式现在在迁移到版本化布局后**会自动修复其图标和目标路径**。

说明官方最终也意识到了问题，并采用了和我相同的思路：**同时修复 `Icon=` 和 `Exec=`**，使快捷方式在版本迁移后能完整恢复可用性。


### 五、我的实践与思考

#### 我做了什么
在理解这个问题的基础上，我补全了缺失的 `Exec=` 路径动态更新逻辑，使快捷方式的修复从“半自动”升级为“全链路自愈”。

#### 具体实现思路
1. 解析当前生效的版本符号链接或 `current.json`；
2. 在版本迁移时，同步刷新快捷方式中的 `Icon=` 和 `Exec=` 字段；
3. 不是简单指向“最新版本”，而是通过扫描可用版本目录，选择**有效的、可执行的**路径。

#### 测试用例设计
为保证修复不引入回归问题，我设计了覆盖三类场景的测试用例：

| 类型 | 测试场景 | 预期结果 |
|------|----------|----------|
| **正例** | 正常从 1.20.2 升级到 1.20.3 | 快捷方式的 `Icon=` 和 `Exec=` 都自动更新为新版本路径，启动成功 |
| **反例** | 新版本目录存在但二进制无执行权限 | 不更新 `Exec=`，保留旧路径，并记录告警日志 |
| **边界** | 同时存在多个有效版本目录 | 选择语义化版本最高的有效路径 |
| **边界** | 用户手动修改过快捷方式（非标准格式） | 跳过修复，避免破坏用户自定义配置 |


### 六、小结与收获

这次问题让我体会到几点：

1. **自修复逻辑要完整闭环**。修图标不修路径，等于给用户制造了“看着能用但实际上不能用”的迷惑状态，比直接报错更糟糕。

2. **版本化目录是双刃剑**。它带来了原子更新和回滚能力，但也破坏了外部依赖（如快捷方式、脚本、软链接）的稳定性。设计时需要一并考虑迁移方案。

3. **测试用例要考虑真实世界的复杂性**。版本升级不是简单的“A 改成 B”，还要考虑权限异常、多版本共存、用户自定义配置等边界情况。

4. **技术方案殊途同归**。我当时的修复思路和官方最终在 v1.22.0 发布的方案一致，说明对问题的判断和解决方向是正确的。
